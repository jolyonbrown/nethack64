**Draft upstream issue (r47; not filed: yours to approve)**
> Title: `else` after `if (c) goto label;` is rejected
> v1.32.273 and main (16acc53) reject this valid C with "error 3006: Term starts with
> invalid token 'else'": `int f(int a) { if (a > 1) goto done; else a = 7; done:
> return a; }`. `break`, `continue` and `return` in the same place compile, as does
> `{ goto done; }`. In `Parser::ParseStatement` the `TK_GOTO` case reads the label and
> returns without consuming the `;` (`TK_BREAK`/`TK_CONTINUE` call
> `ConsumeToken(TK_SEMICOLON)`); the leftover `;` ends the `if` before its `else`.
> Consuming it there, as for `break`, looks like the fix (not built or tested here).

**Draft upstream issue (r48; not filed)**
> Title: a conditional as the middle operand of `?:` is rejected
> `int f(int a, int b) { return a ? b ? 1 : 2 : 3; }` gives "error 3006: ':' expected"
> on v1.32.273 and main (16acc53); `a ? (b ? 1 : 2) : 3` compiles. C89 3.3.15 makes the
> middle operand an *expression*, but `Parser::ParseConditionalExpression` parses it with
> `ParseLogicOrExpression`, which stops at the inner `?`. Parsing it as a full (comma)
> expression would accept it, as well as `a ? x, y : z` (not built or tested here).

**Draft upstream issue (r50; not filed)**
> Title: segfault in `InterCodeBasicBlock::LoadStoreForwarding` after `fopen()`
> `FILE *fp; int n; void touch(const char *s) { n = 0; } void load(void) { fp =
> fopen("quest.dat", "r"); touch("x"); }` (plus a `main` calling `load`) crashes
> v1.32.273 and main 16acc53 at `-Os`, `-O2` and `-O3` (`-O0` compiles), deep in the
> recursion of `LoadStoreForwarding`. A function of our own instead of `fopen()`, an
> `int` global, an empty `touch`, or a `touch` taking an `int` or nothing compile.

**Draft upstream issues (r52-r58; not filed)**
> r52. Title: `!!x` evaluates to `x`
> `int f(int x) { return !!x; }` returns 5 for 5 (v1.32.273, main 16acc53), and
> `int r = !!p;` with a pointer `p` is rejected ("Cannot assign incompatible types").
> C89 3.3.3.3: `!E` is 0 or 1 of type int. `Parser::ParsePrefixExpression` applies `!`
> with `Expression::LogicInvertExpression`, whose `EX_LOGICAL_NOT` case returns the
> operand: fine where only the truth value counts, wrong for a value. Keeping the
> collapse to operands that are 0 or 1 already (relational, `&&`, `||`, `!`) fixes it.

> r53. Title: `!` of a constant is not a constant in an initializer
> `static int k = !0;` and `struct { int v; } s = { !0 };` give "error 3008: Constant
> initializer expected"; `(0 == 0)` compiles. `Expression::ConstantFold` has no case
> for `EX_LOGICAL_NOT`.

> r54. Title: comma expression rejected as an `if`/`while`/`do`/`switch` condition
> `while (m = step(), m < 5) ;` gives "error 3006: ')' expected"; so do `if (a, b)`,
> `do ... while (a, b);` and `switch (a, b)`. `for (a, b; ...)` and `while ((a, b))`
> compile. `ParseParenthesisExpression` and `ParseSwitchStatement` call
> `ParseExpression`, which stops at the comma; `ParseListExpression` would take it.

> r55. Title: `const static int x;` is rejected
> "error 3006: Declaration starts with invalid token 'static'", at file and block
> scope; `static const` compiles. C89 3.5 allows the specifiers in any order.

> r56. Title: `case`/`default` label inside a nested block of a switch is rejected
> `switch (t) { case 2: if (c) { x = 2; break; default: return -1; } }` gives
> "Term starts with invalid token 'default'". `ParseSwitchStatement` only sees labels
> directly in the switch body (Duff's device has the same shape).

> r57. Title: several function declarators in one declaration break later calls
> `static void fa(void), fb(int), fc(void);` then calls `fa(); fb(2); fc();` with the
> definitions after `main`: "error 3045: Ambiguous function call 'fa'". One declaration
> per function compiles.

> r58. Title: `?:` argument for an unused parameter rejected at -O2/-Os
> `void ignore(const char *s) { }` called as `ignore(c1 ? "x" : pick())` (`pick`
> returns `const char *`) gives "Incompatible conditional types" at -O2 and -Os, not at
> -O0/-O1, and not once `ignore` reads `s`.
