**Draft upstream issue (r47; not filed: yours to approve)**
> Title: `else` after `if (c) goto label;` is rejected
> v1.32.273 and main (16acc53) reject this valid C with "error 3006: Term starts with
> invalid token 'else'": `int f(int a) { if (a > 1) goto done; else a = 7; done:
> return a; }`. `break`, `continue` and `return` in the same place compile, as does
> `{ goto done; }`. In `Parser::ParseStatement` the `TK_GOTO` case reads the label and
> returns without consuming the `;` (`TK_BREAK`/`TK_CONTINUE` call
> `ConsumeToken(TK_SEMICOLON)`); the leftover `;` ends the `if` before its `else`.
> Consuming it there, as for `break`, looks like the fix (not built or tested here).

**Draft upstream issue (r48; not filed)**
> Title: a conditional as the middle operand of `?:` is rejected
> `int f(int a, int b) { return a ? b ? 1 : 2 : 3; }` gives "error 3006: ':' expected"
> on v1.32.273 and main (16acc53); `a ? (b ? 1 : 2) : 3` compiles. C89 3.3.15 makes the
> middle operand an *expression*, but `Parser::ParseConditionalExpression` parses it with
> `ParseLogicOrExpression`, which stops at the inner `?`. Parsing it as a full (comma)
> expression would accept it, as well as `a ? x, y : z` (not built or tested here).
