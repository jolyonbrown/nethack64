**The C128's screen was black (fc40 to fc46; fixed in fc47)**
- A screenshot of fc46 (`tools/vice.py screenshot --vdc`, new: x128's VDC canvas) was all black,
  though the VDC's RAM held the map. Two faults, both hidden because every test read the screen
  RAM as text:
  - every character had colour 0: `s80_putca()`'s `rgbi[attr & 15] | (attr & S80_REVERSE ?
    ATTR_REVERSE : 0)` read the table with Y never loaded, a compiler bug (r92, compat #99):
    `JoinTAXARange()` moved the `ORA tab,y` above the `TAY`. The pin, the far fork and upstream
    16acc53 all do it. vdc80.c now takes the colour first; far fork commit 28 fixes the pass
    (`make check` 1,731/1,731); fc48, fc47 linked with it, has the same code as fc47 (comments
    apart): nothing else in the game hit it.
  - the font was never loaded: `--main port`'s `main()` (c64main.c) never called `s80_init()`,
    so the VDC kept the KERNAL's screen-code font. It does now, after `nh_far_init()`.
- fc47 drew "Who are you?" in the project's font, then failed at start-up ("Memory allocation
  failed"): `fontvdc[]` (768 bytes), defined in a header, was out of bankgen's reach
  ("no definition") and stayed resident, so HeapStart moved up 776 bytes. tools/mkfont4x8.py
  now gives the bytes as a macro and vdc80.c defines the table, which goes to bank 55.
- fc49 (that, far31): HeapStart $64F0 (fc46 $64E8: the new call's stub); the replay's Dlvl 2
  drawn on the VDC, light grey on black; 1,240 bytes of near heap free; soft SP $7CE1.
  `make test` 6/6 after the font change.
